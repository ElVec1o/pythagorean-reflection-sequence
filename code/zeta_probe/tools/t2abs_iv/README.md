# t2abs_iv -- verified enclosure of the rectangle bound of Lemma `lem:T2abs`

Paper 2, Lemma `lem:T2abs`: for `tau <= 0.02` and any argument `X` with
`tau X^2 in [2e^{-tau}, 2]`,

    |T_2(X)| <= 0.17 tau^{1/4}.

The proof reduces this to an explicit contour majorant. With `w = sqrt(2/tau)`,
`sigma_*` the largest half-odd-integer below `2w`, `R = {1/2 <= Re s <= sigma_*,
|Im s| <= X/2}`, `M = 2s`,

    |T_2| <= (1/2 pi) * contour integral over dR of  |X^{2s} g_s / Gamma(2s+1)| * |pi/sin(pi s)|
             + sum_{n > sigma_*} X^{2n}/(2n)!

with the amplitude majorants of Lemma `lem:Bbounded`:

    |g_s| <= 1 + e^{30.3 sqrt(tau)}                                     everywhere on the strip,
    |g_s| <= b e^b,  b = (tau^2/24)|M^3/3 + M^2/2 - M/3| + 0.02 tau^{3/2},  where |M| <= 2w.

This program bounds that majorant **from above, uniformly over parameter boxes**,
rather than evaluating it at sample values of `tau`.

## What it certifies

`scan wmax` runs a branch and bound over the two-parameter region

    w in [10, wmax],    X in [w e^{-tau/2}, w],    tau = 2/w^2,

which is exactly the region the lemma quantifies over, restricted to
`tau >= 2/wmax^2`. A box passes when the enclosed upper bound of the majorant
over the whole box is at most the smallest value of `0.17 tau^{1/4}` on the box;
otherwise the box is bisected in whichever of `w`, `X` is relatively wider.
Boxes are clipped to `w e^{-tau/2} <= X <= w` before evaluation. `sigma_*` is
constant on each initial block `w in ((2j+1)/4, (2j+3)/4]`, and the blocks tile
`[10, wmax]`, so no box straddles a jump of the contour.

The range `tau < 2/101^2` is **not** covered here and cannot be: it is an
infinite range of `tau`. It is closed by the explicit-constant analytic estimate
proved in the lemma and regenerated by `../../t2abs_smalltau.py`.

## Arithmetic model

MPFR (`rug`) interval arithmetic with outward directed rounding on every
operation (`src/iv.rs`). MPFR is correctly rounded for `+ - * / sqrt exp log
sinh cosh tanh atan lgamma`, so the endpoints are exact outward roundings and no
epsilon fudge appears in the interval layer. The only floating-point slack in
the program is in the quadrature bookkeeping: cell contributions are converted
to `f64` outward and widened by a relative `1e-15` (three roundings at `2^-53`),
and the per-edge totals are re-accumulated in MPFR with directed rounding.

Two ingredients are treated analytically so that the enclosure stays tight:

* On the left edge `Re s = 1/2` and the right edge `Re s = sigma_*` the kernel
  is written in closed form, using `|Gamma(1+iy)|^2 = pi y / sinh(pi y)` and, on
  the right edge, `|Gamma(m+iy)|^2 = |Gamma(1+iy)|^2 prod_{k<m}(k^2+y^2)` for
  the integer `m = 2 sigma_* + 1`. No Stirling formula is used there.
* On the horizontal edges the integration variable is `u = (2 sigma + 1)/X`, and
  the exponent is regrouped so that every term of size `a log X` cancels
  symbolically:

      log[ X^{2 sigma} pi / (sinh(pi X/2) |Gamma(a+iX)|) ]
        = (1/2)log 2pi - log(1-e^{-pi X}) - (1/2)log X
          + X psi(u) + (1/4)log(1+u^2) - Re mu(a+iX),

  `psi(u) = u - arctan u - (u/2)log(1+u^2)`, `|mu(z)| <= mu(Re z) <= 1/(12 Re z)`
  by Binet's first integral. `psi` is monotone (`psi' = -(1/2)log(1+u^2)`), so
  its enclosure on a `u`-cell is exact up to rounding, and `X` occurs once in
  every factor, so the enclosure over an `X`-interval is tight. Evaluating the
  unregrouped difference instead inflates the exponent enclosure by a factor
  ~20 per cell and the scan does not converge.

## Usage

    cargo build --release --offline
    ../runcap.sh 14000 7200 ./target/release/t2abs_iv scan 101 96 6
    ../runcap.sh 14000 7200 ./target/release/t2abs_iv scan 101 160 6      # second precision
    ./target/release/t2abs_iv point 10 96 1e-2                            # one (tau, X) point
    ./target/release/t2abs_iv scan 101 96 6 0.166                         # a sharper constant

`scan <wmax> [prec_bits] [threads] [constant]`, `point <w> [prec_bits] [reltol]`.
Setting `T2DBG=1` prints one line per box.

## Results (2026-08-15, MPFR, this machine)

    scan 101 96  6  ->  183 blocks, 232 boxes, 492569 cells, PASS, 25 s, peak RSS 4 MB
    scan 101 160 6  ->  identical box count and identical worst ratio
    worst ratio over the accepted cover:  |T_2| <= 0.169780 tau^{1/4}
    scan 101 96  6 0.166  ->  PASS (252 boxes)

The worst-ratio figure is a box-level number: it compares the largest bound on a
box against the smallest `tau^{1/4}` on the same box, so it exceeds the pointwise
supremum. At the extremal point `tau = 0.02`, `X = w = 10` the pointwise
enclosure is

    point 10 96 1e-2  ->  |T_2| <= 0.061685 = 0.164031 tau^{1/4}

against the value `0.16233 tau^{1/4}` that the older adaptive-quadrature
certificate `../../t2abs_certificate.py` reports there; the enclosure is 0.7%
above it, as an upper bound should be.

## Cross-checks

`point` reproduces every entry of the seven-value table of
`../../t2abs_certificate.py` (mpmath, adaptive quadrature, dps 30 and 50) from
above, at `tau = 2e-2, 1.27e-2, 1e-2, 5e-3, 1e-3`. The two programs share no
code: this one uses MPFR intervals and closed-form/Stirling kernels, that one
uses mpmath adaptive quadrature and `mpmath.gamma`.
